# Coverage and verification boundaries

**Snapshot:** 2026-10-04. Breadth means each topic has a source/analysis workflow;
it does not mean every live fact, language, scenario or narrative is stored offline.

| Area | Local readiness | Required external verification / gap |
|---|---|---|
| English expansion base cards, Sets 1–14 | Complete base-number coverage; 3,515 printing records, 2,784 identity groups | Exact images/corrections for disputed text; export retrieval time unknown |

| Reprints and physical variants | API identity grouping, printing/finish metadata, aliases | Not a complete collector or multilingual oracle |
| Functional card text | All 137 differing identity groups resolved for October 4; 510 official images cached; raw texts retained | Non-conflicting records are API-consistent, not individually certified; historical corrections/localized oracle incomplete |

| Core and Infinity | Separate dated policy, structural checks, known exceptions | Event/region changes; historical dates before July 17 need contemporary policy |
| Sealed and Draft | Pool-based workflow and automated quantity/minimum checks | Actual pool, product and event instructions; set rankings remain inference |
| Preconstructed and Pack Rush | Official baseline and cached Pack Rush rules | Exact supplied product and authorized event changes |

| Curated answers and evaluation | 89 dated answers; 109-case FAQ/evidence benchmark plus 24 compound claim/source/math contracts | Reference-assisted fixtures; independent prose/expert grading pending; no unrestricted certification |

When a cell requires verification, retrieve the specific source and answer the
supported portion. Never replace a missing rule, result, price or narrative detail
with a confident-sounding invention. Complete base-card data enables mechanical
analysis; it is not evidence that a deck is optimized or a matchup has been measured.
